# Speed II: tap → first meaningful paint (2026-10-11, Blueprint 23)

Local stack, synthetic data only (a founder's network, one member, ₦1,000.00 of income), measured
with `frontend/tests/e2e/speed.e2e.ts`:

```
E2E_SPEED=1 E2E_SPEED_OUT=/tmp/speed.json scripts/e2e-local.sh speed.e2e.ts
```

- **Profile:** 390 × 844 touch viewport, 150 ms RTT, 1.6 Mbps down, CPU × 4 (Chrome DevTools
  Protocol), plus 300 ms on every `/api` read for the Worker → Supabase (London) trip from Lagos.
  Service worker blocked so every fetch is throttled; each run is a new browser context (no
  device cache).
- **Flow:** sign in as the President, reload Home under throttling, stay idle 12 s, then tap each
  route from More: **cold** (first visit this session) and **warm** (revisit).
- **Page swap** (`nav`): tap until the URL changed and the old page is gone (the new page or its
  frame is on screen). **Data on screen** (`paint`): tap until the route's data marker shows
  (team/offices: ₦1,000.00; members: "N members"; audit: "N events"; invitations: the member's
  email).
- **What the times mean:** both are taken from the page's DOM (`requestAnimationFrame`). With
  the page swap (after only), the new page starts fading in on that frame and is fully opaque up
  to 180 ms later; the numbers are when it starts to show, not when the fade ends (Greptile on
  PR #60).
- **Before:** `origin/main` 19b659c (Blueprint 20 caching on Home, Activity, Team, Wallets,
  Offices, Members, Settings). **After:** this branch. 3 runs each; medians.

## Reading it
- **Cold taps:** the page now changes in about 55–60 ms instead of 200–380 ms, because every
  screen's code was fetched while idle. Data still needs its round trip (here 150 ms RTT +
  300 ms), so first data shows at about 510–520 ms instead of 670–850 ms.
- **Warm taps on pages Blueprint 20 didn't cache** (audit, invitations): 487 ms → about 60 ms.
- **Warm taps on pages that were already cached** (team, members, offices) are about 25–35 ms
  slower (20–33 → 44–55 ms). That is the page swap: the browser captures the old page for one or
  two frames (at CPU × 4) before the new one is drawn. Without throttling it is about one frame.
- **Tab bar:** the tapped tab now turns current on the tap (`navigating.to`), not when the page
  has loaded; before, a cold tap's highlight waited for the page swap above (200–380 ms).
